2. Persiapan Konektivitas Jaringan

Pilih salah satu metode koneksi di bawah ini sesuai situasi demo:

Opsi A: Demo Offline (Tatap Muka & Hotspot HP Bersama)

  1. Salah satu orang menyalakan Hotspot HP. Kedua laptop wajib connect ke Wi-Fi yang sama.
  2. Di Host 1, ketik ipconfig di PowerShell untuk melihat IP Wi-Fi (misal: 192.168.43.15).
  3. Di Host 2, buka tugas-2/host2/docker/docker-compose.yml dan atur:
    MQTT_BROKER_HOST: "192.168.43.15" dan MQTT_BROKER_PORT: "1883".
  4. Dashboard dibuka Host 2 di browser via http://192.168.43.15:8080.

Opsi B: Demo Online (Jarak Jauh / Port Tunneling Internet)

  1. Di Host 1, jalankan tugas-2\start_internet_tunnel.bat (double-click di Windows).
  2. Akan terbuka 2 jendela CMD. Salin alamat tunnel publik yang muncul:
    • Tunnel TCP (Port 1883): misal tcp://gcdyg-182-8-97-149.run.pinggy-free.link:36219
    • Tunnel HTTPS (Port 8080): misal https://kqaem-2404-c0-b601.run.pinggy-free.link
  3. Di Host 2, masukkan Host & Port TCP tersebut ke docker-compose.yml:
    MQTT_BROKER_HOST: "gcdyg-182-8-97-149.run.pinggy-free.link"
    MQTT_BROKER_PORT: "36219".
  4. Host 2 dan Penguji membuka Web Dashboard langsung via link HTTPS tunnel di atas.

4. Pertanyaan Penguji & Jawaban Teknis Tepat

Q1: Kenapa Web Server diletakkan di VM Linux, bukan langsung di Docker Host 1?
Jawaban: Sesuai instruksi penugasan, penempatan Web Server di VM menguji kemampuan administrasi jaringan Linux murni (Alpine), pengelolaan antarmuka kernel eth0, routing gateway NAT 10.0.2.2, serta isolasi keamanan antar lingkungan server fisik dan virtual.
Q2: Bagaimana Web Server di VM (10.0.2.15) bisa mengakses MySQL (3306) di Windows Host?
Jawaban: VirtualBox mode NAT secara arsitektur menetapkan IP 10.0.2.2 sebagai alias host fisik Windows. Di Windows Host, port 3306 Docker di-bind ke 0.0.0.0:3306 dan firewall telah kami izinkan, sehingga query TCP dari dalam VM diteruskan langsung ke container MySQL.
Q3: Kenapa Host 2 tidak langsung konek dan insert ke MySQL Host 1 saja?
Jawaban: Dalam best practice keamanan dan arsitektur IoT modern, database tidak boleh diekspos langsung ke perangkat luar. Menggunakan Message Broker MQTT memberikan loose coupling, efisiensi bandwidth tinggi pada jaringan edge, serta ketahanan buffer data (fault tolerance).
Q4: Mengapa tadi saat port tunneling harus menggunakan 127.0.0.1 bukan localhost?
Jawaban: Di Windows 10/11, OpenSSH me-resolve localhost ke alamat IPv6 loopback (::1). Karena port forwarding VirtualBox dan Docker hanya listen pada IPv4 (0.0.0.0), forwarding ke IPv6 ditolak (connection refused). Penggunaan 127.0.0.1 memaksa rute IPv4 murni sehingga koneksi tunnel berhasil 100%.
