Mekanisme Akses Web Server pada Host 1 oleh Host 2 Melalui Network Address Translation (NAT) dan Port Forwarding

Mata Kuliah: Jaringan Komputer Lanjut (A)
Institusi: Institut Teknologi Sepuluh Nopember (ITS)
Kelompok: Dzaky Haady & Nicholas Benaya
Topik: Tugas Pelengkap Demonstrasi Virtualisasi

1. Topologi dan Batasan Akses Langsung pada Mode NAT

Arsitektur pengujian melibatkan dua komputer fisik pada jaringan LAN lokal (Wi-Fi) yang sama. Host 1 (Server) memiliki IP fisik 172.20.10.8 dan menjalankan hypervisor VirtualBox. Di dalam VirtualBox, berjalan mesin virtual VM1-Jarkom (Alpine Linux) yang mengeksekusi Web Server Flask pada port TCP 8080. Antarmuka virtual VM (eth0) menerima alamat privat 10.0.2.15/24 dari DHCP internal VirtualBox. Sementara itu, Host 2 bertindak sebagai klien di LAN fisik (misal IP 172.20.10.5).

Secara default, mode jaringan NAT mengisolasi VM di dalam subnet virtual tersendiri. Alamat 10.0.2.15 bersifat non-routable di jaringan luar. Router LAN fisik tidak memiliki entri tabel perutean (*routing table*) menuju subnet 10.0.2.0/24, sehingga paket yang dikirim langsung oleh Host 2 ke 10.0.2.15 akan langsung di-drop.

[ Host 2: Klien ] (172.20.10.5) ─── HTTP GET 172.20.10.8:8080 ───► [ Host 1: Windows Fisik ] (172.20.10.8) │ VirtualBox NAT Engine (Port Forwarding) │ Translasi DNAT: Dst -> 10.0.2.15:8080 ▼ Translasi SNAT: Src -> 10.0.2.2:PortVirtual [ Guest VM: Alpine Linux ] (10.0.2.15:8080)

2. Prinsip Kerja Port Forwarding (Destination NAT pada Layer 4)

Untuk menjembatani akses tanpa mengubah adaptor VM menjadi Bridged, diterapkan konfigurasi Port Forwarding pada VirtualBox: TCP | Host: 0.0.0.0:8080 -> Guest: 10.0.2.15:8080. Konfigurasi ini memerintahkan driver VirtualBox pada Host 1 untuk membuka *socket listening* pada seluruh interface host (0.0.0.0:8080). Setiap segmen TCP yang menuju port 8080 pada IP fisik Host 1 dicegat oleh engine NAT dan ditranslasikan ke dalam VM.

3. Siklus Alur Perjalanan Paket Data (Packet Walkthrough)

  1. Permintaan dari Host 2 (Outbound Client Request): Peramban di Host 2 mengirim paket TCP SYN ke alamat fisik Host 1: [Src: 172.20.10.5:54321, Dst: 172.20.10.8:8080]. Paket melintasi switch/router Wi-Fi LAN menuju kartu jaringan fisik Host 1.
  2. Penerimaan dan Translasi Ganda oleh VirtualBox (DNAT & SNAT): Windows Firewall mengizinkan paket masuk pada port 8080. Engine NAT VirtualBox mencegat paket pada soket yang terbuka dan mengeksekusi dua translasi header:
    • Destination NAT (DNAT): Mengubah alamat tujuan dari 172.20.10.8:8080 menjadi alamat IP privat guest 10.0.2.15:8080.
    • Source NAT (SNAT): Mengubah alamat sumber dari 172.20.10.5 menjadi alamat gateway virtual 10.0.2.2. Langkah ini krusial agar paket balasan dari kernel VM otomatis dikembalikan ke interface virtual gateway NAT Host 1.
  3. Pemrosesan oleh Web Server di VM: Paket masuk melalui antarmuka eth0 VM. Kernel Alpine Linux menyerahkan muatan ke proses Python Flask. Web server memproses kueri telemetri ke database MySQL di Host 1 (10.0.2.2:3306), menyusun response HTTP 200 OK, lalu mengirimkannya kembali ke default gateway 10.0.2.2.
  4. Jalur Balik Respons (Reverse Address Translation): Engine NAT VirtualBox menerima respons dari VM, mencocokkan *session state table*, mengembalikan alamat asal menjadi 172.20.10.8:8080, dan mengarahkan tujuan kembali ke 172.20.10.5:54321 melalui stack TCP/IP Windows fisik.
  5. Penerimaan di Host 2: Host 2 menerima paket balasan dan merender dashboard IoT secara transparan tanpa perlu mengetahui bahwa server fisik di belakangnya berada dalam lingkungan virtual terisolasi.

4. Kesimpulan

Mekanisme Port Forwarding VirtualBox menyelesaikan masalah isolasi perutean pada mode NAT melalui kombinasi socket binding pada Host OS serta translasi alamat Layer 4 (DNAT dan SNAT). Pendekatan ini menjaga keamanan host virtual karena antarmuka VM tetap terisolasi dari pemindaian langsung di LAN luar, namun layanannya tetap dapat diakses secara publik dan efisien oleh Host 2.
